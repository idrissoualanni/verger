# RBAC centralisé + 401/403 + redirect login — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Centraliser les permissions RBAC du Verger dans une matrice unique, distinguer 401 (non connecté) de 403 (rôle insuffisant), rediriger le frontend vers /login sur 401, et fermer l'escalade de privilèges au signup.

**Architecture:** La matrice de permissions vit dans `@verger/shared` (déjà importé par les routeurs — pas de nouveau bundling). Chaque copie API (web = prod single worker, api = copie historique) reçoit un helper Hono `requirePerm(c, permission)` qui retourne 401 sans session, 403 avec session mais rôle insuffisant. Le client `api.ts` gère le 401 par redirect vers /login et le 403 par message explicite. `databaseHooks.user.create.before` force `role: "SECRETAIRE"` à toute inscription — le rôle PROPRIETAIRE ne se pose plus que par mise à jour directe en base (script create-owner).

**Tech Stack:** Hono, Better Auth 1.6.26 (signature hook vérifiée dans `node_modules/@better-auth/core` : `before(user, ctx) → { data: {...} } | undefined`), Next.js 16 App Router, Drizzle, TypeScript.

**Validation :** Le monorepo n'a **aucun runner de test** (vérifié : ni vitest ni jest ni @testing-library, aucun script `test`). La validation suit le pattern du plan `2026-08-14-corrections-completes.md` : **typecheck + scénario curl complet en prod**. Ne pas introduire de runner dans ce plan (YAGNI).

**Contexte des décisions (entérinées avec l'utilisateur) :**
- Option A choisie : 401 côté client → redirect `/login?callbackUrl=...` (le middleware edge de session est neutralisé depuis le passage single worker).
- Matrice maison dans `@verger/shared` plutôt que CASL/Casbin : 5 rôles statiques × 12 modules — un framework complet serait de la sur-ingénierie (position argumentée et acceptée).
- La copie `apps/web/src/lib/api/` est celle qui tourne en prod (single worker). `apps/api/src/` est la copie historique — maintenir la parité pour éviter la dérive.

 * @verger/shared — Matrice RBAC centralisée.
 *
 * Convention : une permission = `${module}:${action}`.
 * Le helper Hono `requirePerm` (dans chaque copie API) consomme cette matrice.
 * ENSEIGNANT n'a aucune permission tant que les modules absences/notes
 * ne sont pas câblés (AGENT.md §4 — activation progressive).
 */
import type { UserRole } from "./constants";

export const MODULES = [
  "levels",
  "students",
  "grades",
  "absences",
  "whatsapp",
  "events",
  "invoices",
  "payments",
  "expenses",
  "staff",
  "travel",
  // Modules de navigation (pas de route REST associée — servent au filtrage sidebar)
  "dashboard",
  "notifications",
  "journal",
] as const;
export type Module = (typeof MODULES)[number];

export const ACTIONS = ["read", "create", "update", "delete", "stats"] as const;
export type Action = (typeof ACTIONS)[number];

export type Permission = `${Module}:${Action}`;

const OWNER_MODULES = [
  "levels",
  "students",
  "grades",
  "absences",
  "whatsapp",
  "events",
  "invoices",
  "expenses",
  "staff",
] as const;
const CRUD: Action[] = ["read", "create", "update", "delete"];

/** PROPRIETAIRE : tout, sur tous les modules. */
const OWNER_PERMISSIONS: readonly Permission[] = [
  ...OWNER_MODULES.flatMap((m) => CRUD.map((a) => `${m}:${a}` as Permission)),
  "payments:read",
  "payments:create",
  "payments:update",
  "payments:delete",
  "payments:stats",
  "travel:read",
  "travel:create",
  "travel:update",
  "travel:delete",
  "dashboard:read",
  "notifications:read",
  "journal:read",
];

export const ROLE_PERMISSIONS: Record<UserRole, readonly Permission[]> = {
  PROPRIETAIRE: OWNER_PERMISSIONS,
  SECRETAIRE: ["payments:read", "payments:create", "payments:update", "payments:delete"],
  COMPTABLE: ["payments:read", "payments:delete", "payments:stats"],
  ENSEIGNANT: [],
  AGENT: ["travel:read", "travel:create", "travel:update", "travel:delete"],
};

/** Vérifie si un rôle possède une permission. Retourne false si rôle absent/inconnu. */
export function hasPermission(
  role: UserRole | null | undefined,
  permission: Permission
): boolean {
  if (!role) return false;
  const perms = ROLE_PERMISSIONS[role];
  return perms ? (perms as readonly string[]).includes(permission) : false;
}
```

/**
 * Helper Hono RBAC — consomme la matrice @verger/shared.
 * 401 = non connecté ; 403 = connecté mais rôle insuffisant.
 */
import { hasPermission, type Permission } from "@verger/shared/src/permissions";

type AuthContext = { var: { auth: any }; req: { raw: Request } };

/**
 * Vérifie session + permission. Retourne l'utilisateur ou une Response d'erreur.
 * Usage : `const auth = await requirePerm(c, "levels:read"); if ("res" in auth) return auth.res;`
 */
export async function requirePerm(
  c: AuthContext,
  permission: Permission
): Promise<{ user: any } | { res: Response }> {
  const session = await c.var.auth.api.getSession({ headers: c.req.raw.headers });
  if (!session?.user) {
    return { res: c.json({ error: "Non connecté" }, 401) };
  }
  if (!hasPermission(session.user.role, permission)) {
    return { res: c.json({ error: "Accès refusé pour votre rôle" }, 403) };
  }
  return { user: session.user };
}
```
